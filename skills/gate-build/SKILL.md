# gate-build — 実装(コンポーネント/単体テストまで)

## 前提チェック

`.specs/stories/<slug>/TASKS.md` が存在しない場合は、先に `gate-plan` を完了させるようユーザーに促す。

## 手順

1. `STORY.md`, `DESIGN.md`, `TASKS.md` を読む。
2. `TASKS.md` の未完了タスクを上から順に(依存関係を尊重して)実装する。DESIGN.mdの方針に沿う。ユーザーが特定のタスク番号を指定した場合はそれを優先する。
3. 各タスクについて:
   - 実装に対応するコンポーネント/単体テストを書く(ISTQBのComponent Testingレベル。統合・システム・受け入れレベルの検証はここでは行わない)。
   - 実装後、そのタスクの `TASKS.md` のチェックボックスに `[x]` を付ける。
   - 意味のある単位ごとに立ち止まり、まとめて全タスクを無言で終わらせない。
4. 技術選定・設計判断はここでは行わない(gate-designで決着済みという前提)。

## 実装中に計画が破綻した場合のフィードバックループ

実装を進める中で「TASKS.mdのタスクが想定通りに進められない」「DESIGN.mdの技術方針そのものが現実的でないと判明した」ことが起こり得る。その場合、その場しのぎで対処しない:

1. 実装を止め、何が起きたか・なぜ計画通りにいかないか・どのアーティファクトまで遡って見直す必要があるか(TASKS.mdだけか、DESIGN.mdまで遡るか、まれにSTORY.mdのScenario自体が非現実的だったか)をユーザーに説明する。
2. **ユーザーの同意を得てから**、該当するフェーズ(`gate-plan`/`gate-design`/まれに`gate-story`)をこのストーリー単位で再実行し、アーティファクトを改訂する。改訂内容と理由を短く記録する(何を変えたか・なぜか。既存内容を無言で上書きしない)。
3. 同意を得た上で `gate-build` を改訂後の内容から再開する。

## 完了後

すべての対象タスクが完了したら `.specs/stories/<slug>/STORY.md` のステータスを更新し、次は `gate-test` に進むことを案内する。
