# spec-research — 関連情報調査

要件定義・設計の判断材料として、Web上の関連情報(先行事例、ベストプラクティス、既知の落とし穴、規制/標準、関連ライブラリの現状)を調査する。ペルソナ(視点)ではなく、独立したアクション(行動)として実装する。

## 前提

`.specs/<slug>/` が存在しない場合、機能に紐づかないプロジェクト全体の調査として扱ってよい(その場合は手順7の保存先を `.specs/research/<topic-slug>.md` とする)。

## 手順

1. 調査したいトピックを明確にする。`.specs/<slug>/spec.md` があれば、そこから調査すべき論点(採用予定の技術・ドメイン・規制など)を抽出する。曖昧なら何を知りたいかユーザーに確認する。
2. **WebSearch** で複数の観点から検索する: 類似機能の実装例、業界のベストプラクティス、よくある落とし穴・失敗事例、関連する標準・規制、候補となる技術/ライブラリの現状(メンテナンス状況・既知の問題)。
3. 有望なページは **WebFetch** で内容を確認する。
4. 一次情報・信頼できる情報源を優先し、古い情報や単一のブログ記事だけに依拠しない。
5. `.specs/<slug>/research.md`(または `.specs/research/<topic-slug>.md`)を以下の構成で書く。

   ```markdown
   # Research: <トピック>

   ## 調査した論点
   - ...

   ## わかったこと
   - ...(先行事例・ベストプラクティス・落とし穴など)

   ## この機能への示唆
   - ...(spec/designの判断にどう影響するか)

   ## 未解決・要追加調査
   - ...

   ## Sources
   - [タイトル](URL)
   ```

6. `spec.md` や `design.md` を作成・更新中であれば、この調査結果を踏まえて反映するようユーザーに促す。`domain-specialist` や `tech-lead` ペルソナがレビュー・討議で参照できるよう、ファイルパスを伝えておく。
