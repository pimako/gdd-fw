# gate-init — プロジェクト立ち上げ(インセプション)

Gate-Driven Development(GDD)の3階層構造のうち、**プロジェクト単位で一度だけ**行う立ち上げ作業。以降のすべてのストーリー・イテレーションはここで作った土台を参照する。

## 共通ルール(このプラグインの全スキルで共通)

- 成果物はすべて**対象プロジェクト直下**の `.specs/` に格納する(このプラグイン自身のリポジトリではなく、ユーザーが今取り組んでいるプロジェクトのルート)。
- `<story-slug>` は kebab-case、英数字とハイフンのみ、ストーリーの内容を要約したもの。
- 推測で埋めない。曖昧な点は **AskUserQuestion** で確認する。

## 手順

1. `.specs/INCEPTION.md` が既にあれば、上書きしてよいか確認してから進める(通常は一度きりのはずなので、再実行は意図的な見直しとして扱う)。
2. インセプションデッキの要点をヒアリングする(AskUserQuestion中心。ソロ開発向けに簡略化してよいが、要素は落とさない):
   - **エレベーターピッチ**: このプロダクト/プロジェクトは何のために存在するか
   - **やらないことリスト**: プロジェクト全体としてスコープ外にすること
   - **ご近所さん(ステークホルダー)**: 誰が関係するか(ソロ開発なら「将来のユーザー像」でもよい)
   - **解決策の概要**: 技術的な大まかな方針・アーキテクチャのイメージ
   - **リスク**: 夜も眠れなくなるような懸念事項
   - **期間感**: どのくらいの期間・規模を想定しているか
3. `.specs/INCEPTION.md` を書く。
4. `.specs/PERSONAS.md`(ペルソナロスター)が無ければ `gate-team` の実行を推奨する。
5. `.specs/BACKLOG.md` を空のマスターストーリーリストとして初期化する(フォーマットは`gate-story`のSKILL.md参照)。
6. 次は `gate-team`(未設定なら)、続けて `gate-story` で最初のストーリーを書き始めることを案内する。

## INCEPTION.md フォーマット

```markdown
# Inception

## エレベーターピッチ
...

## やらないことリスト
- ...

## ご近所さん(ステークホルダー)
- ...

## 解決策の概要
...

## リスク
- ...

## 期間感
...

## 作成日
<ISO日付>
```
