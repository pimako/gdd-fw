# spec-discuss — アドホック・ペルソナ討議

`spec-review`/`spec-verify` は「フェーズに応じて機械的にペルソナを呼ぶ」のに対し、このスキルは**ユーザーが投げた任意のトピックに対して、関連するペルソナを都度選び、お互いの意見を見て反応する討議**をさせる。独立並列→統合の `spec-review` とは異なり、こちらは意図的に**ラウンドをまたいでお互いに反応させる**(構造化ディベート)。

## 手順

1. ユーザーからトピック・論点(自由記述)を受け取る。何を決めたいのかが曖昧なら1点だけ確認する(推測で補わない)。
2. ペルソナを選ぶ:
   - `.specs/PERSONAS.md` があればそこから、無ければ `personas/` ライブラリ全体から、トピックの内容とペルソナのrole/goalの関連度で **3〜5人**を選ぶ。
   - ユーザーが特定のペルソナを名指しした場合はそれを優先する。
3. 参照可能な文脈を集める: アクティブな機能があれば `.specs/<slug>/spec.md`, `design.md`, `research.md`。
4. **Round 1**: 選ばれたペルソナぶんの `persona-agent` を並列起動(1メッセージ内)。各ペルソナは他者の意見を見ずに、トピックへの初期見解を述べる。
5. **Round 2**: 各ペルソナに、Round 1の全員の発言を渡し、賛成/反対/補足を明示させたうえで見解を述べさせる(persona-agentの討議用途)。
6. **最大2ラウンドで打ち切る**(3ラウンド目以降はバイアス増幅のリスクがあるため行わない)。
7. 合意点・対立点・(対立が残るなら)人間が判断すべき論点を整理したサマリーを書く。
8. 保存先を決めて書く:
   - アクティブな機能があれば `.specs/<slug>/discussions/<topic-slug>.md`
   - なければプロジェクト直下 `.specs/discussions/<topic-slug>.md`
9. サマリーをユーザーに提示する。

## 出力フォーマット

```markdown
# Discussion: <トピック>

## 参加ペルソナ
- ...(選定理由も一言)

## Round 1(初期見解)
### tech-lead
...

## Round 2(相互応答)
### tech-lead
(security-engineerの指摘に対して)...

## 合意点
- ...

## 対立点・人間の判断が必要な論点
- ...
```
