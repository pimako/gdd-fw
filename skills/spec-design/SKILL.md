# spec-design — 設計フェーズ

## 前提チェック

`.specs/<slug>/spec.md` が存在しない場合は、先に `spec-spec` を完了させるようユーザーに促し、ここでは進めない。

## 手順

1. `.specs/<slug>/spec.md` と、対象プロジェクトの既存コード・構成を読む。
2. **spec-architect** サブエージェント(Agent tool)に、`spec.md` の内容、プロジェクトの技術スタック・既存パターンの要約を渡して設計を依頼する。複数のアーキテクチャ案がある場合はトレードオフ込みで比較させる。
3. サブエージェントの結果を踏まえ、`.specs/<slug>/design.md` を以下の構成で書く。

   ```markdown
   # Design: <機能名>

   ## 採用するアプローチ
   選んだ方針と、選ばなかった代替案・その理由(簡潔に)。

   ## アーキテクチャ概要
   コンポーネント構成、データフロー(必要ならテキストの図解)。

   ## 主要な技術判断(ADR的記述)
   - 判断: ... / 理由: ... / トレードオフ: ...

   ## 変更対象ファイル・モジュール(概観)
   - ...

   ## リスク・懸念事項
   - ...
   ```

4. 影響範囲が大きい、または複数の妥当な選択肢がある場合は、設計案をユーザーに提示し **AskUserQuestion** または通常の確認で承認を取ってから確定する。
5. `.specs/<slug>/STATE.md` を更新(`current_phase: design`、進捗チェック、`updated_at`)。
6. 次は `spec-tasks` に進むことを案内する。
