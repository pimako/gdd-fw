# gate-run — パイプライン オーケストレーター

各フェーズは対応する `gate-*` スキルの手順そのものに従うこと(このファイルは順序とゲートだけを定義する)。

## 全体フロー

1. `.specs/INCEPTION.md` が無ければ `gate-init` を実行する。
2. `.specs/PERSONAS.md` が無ければ `gate-team` の実行をユーザーに一度提案する(必須ではない。断られた場合は暫定ロスターで進む)。
3. アクティブなイテレーションが無ければ `gate-iteration`(計画モード)を実行し、今回扱うストーリー群を決める。バックログにストーリーが無ければ先に `gate-story` で用意する。
4. イテレーション内の各ストーリーについて、以下を順に実行する:
   a. `gate-story` が未完了ならここで完了させる(確認条件を**確定の同意を得る**まで先に進まない — ゲート1)。
   b. `gate-design` を実行し、DESIGN.mdをユーザーに提示して確認を取る(影響が小さければ軽い確認でよい — ゲート2)。
   c. `gate-plan` を実行し、TASKS.mdの確定同意を得る(ゲート3)。
   d. ゲート3通過後は `gate-build` → `gate-test` → `gate-check` を連続して実行する。以下の場合は立ち止まってユーザーに報告・確認する:
      - `gate-build`内のフィードバックループが発生した場合(計画変更の同意を求める)
      - `gate-check`が**2ラウンド**を超えてもcritical/majorの指摘を解消できない場合
5. イテレーション内の全ストーリーが`done`になったら `gate-iteration`(ふりかえりモード)を実行する。
6. 次のイテレーションに進むかユーザーに確認し、進む場合は3に戻る。

## 途中再開

各ストーリーの `STORY.md` のステータス、`.specs/BACKLOG.md`、`.specs/iterations/` の状態から、未完了のフェーズ・イテレーションを判定して再開する。すでに完了しているフェーズは再実行しない(ユーザーが明示的にやり直しを指示した場合を除く)。

## 注意

- 各フェーズの詳細な手順・出力フォーマットは重複させず、対応する `gate-*` スキルに委ねる。このスキルは「いつどの順で・どこで止まるか」だけを担う。
