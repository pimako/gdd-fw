# spec-test — テストフェーズ

## 前提チェック

`.specs/<slug>/tasks.md` が存在しないか、実装が明らかに未着手の場合は、先に `spec-implement` を進めるようユーザーに促す。

## 手順

1. `.specs/<slug>/spec.md`(特に受け入れ基準)と実装済みコードを読む。
2. **spec-tester** サブエージェント(Agent tool)に、受け入れ基準と実装差分を渡し、テスト方針の設計と実装(可能なら実行まで)を依頼する。プロジェクトに既存のテストフレームワーク・規約があればそれに従うよう指示する。
3. テストを実行し、結果を確認する。失敗があれば実装に戻って修正するか、ユーザーに報告する。
4. `.specs/<slug>/test.md` を以下の構成で書く。

   ```markdown
   # Test: <機能名>

   ## テスト方針
   ...

   ## 受け入れ基準との対応
   - 受け入れ基準n → <テスト名/ファイル>

   ## 実行結果
   - ...(成功/失敗、カバレッジの所感など)

   ## 未カバーの項目・既知の制約
   - ...
   ```

5. `.specs/<slug>/STATE.md` を更新(`current_phase: test`、進捗チェック、`updated_at`)。
6. 次は `spec-review` に進むことを案内する。
