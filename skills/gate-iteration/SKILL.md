# gate-iteration — イテレーション計画・ふりかえり

ソロ開発向けに、**カレンダー週ではなくストーリー件数/ゴールで区切る**イテレーション。ユーザーが「このストーリー群を今回のイテレーションとする」と宣言する。

## 状態判定

`.specs/iterations/` を確認し、以下のどちらのモードかを判定する:
- アクティブなイテレーション(`PLAN.md`はあるが`RETRO.md`が無い最新の`<n>`)が無い → **計画モード**
- アクティブなイテレーションがあり、その中の全ストーリーが`done`、またはユーザーが「ここで区切る」と明示した → **ふりかえりモード**
- アクティブなイテレーションがあり、まだストーリーが残っている → 現状を`gate-status`相当で報告し、続行を促す(このスキルでは何もしない)

## 計画モード

1. `.specs/BACKLOG.md` を読み、ステータスが`ready`のストーリーをユーザーと相談しながら選ぶ。
2. 今回のイテレーションのゴール(何を達成したら意味があるか)を決める。
3. 次のイテレーション番号 `<n>` を決め、`.specs/iterations/<n>/PLAN.md` を書く。
4. 選んだストーリーの `STORY.md` のイテレーション欄・ステータス(`in-iteration`)を更新し、`BACKLOG.md`も更新する。
5. 各ストーリーについて `gate-design` → `gate-plan` → `gate-build` → `gate-test` → `gate-check` の流れに進むことを案内する(まとめて`gate-run`に任せてもよい)。

## ふりかえりモード

1. このイテレーションで完了したストーリーをまとめ、ショーケース的な要約(何を届けられたか)を作る。
2. ふりかえり(Keep/Problem/Try、またはユーザーの好む形式)を行う。特に「実装中に計画を見直した回数・理由」(gate-buildのフィードバックループの発生状況)があれば、計画精度の学びとして触れる。
3. `.specs/iterations/<n>/RETRO.md` を書く。
4. 次のイテレーションの計画に進みたいか確認する(進むなら計画モードへ)。

## PLAN.md フォーマット

```markdown
# Iteration <n> Plan

## ゴール
...

## 対象ストーリー
- <story-slug>(見積り: ...)

## 開始日
<ISO日付>
```

## RETRO.md フォーマット

```markdown
# Iteration <n> Retro

## 完了したストーリー(ショーケース)
- <story-slug>: ...

## Keep
- ...

## Problem
- ...

## Try
- ...

## 計画の見直しが発生した箇所(あれば)
- ...
```
