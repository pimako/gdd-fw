# spec-spec — 要件/仕様定義フェーズ

対象プロジェクトの `.specs/<slug>/` が未初期化なら、先に `spec-new` を実行するようユーザーに促してから進める。

## 手順

1. `.specs/<slug>/STATE.md` を読み、対象機能を把握する。
2. ユーザーの要望を読み、以下が曖昧なままなら **AskUserQuestion** で確認する(推測で埋めない):
   - 誰のための機能か / 解決したい問題は何か
   - スコープに含むもの・含まないもの(Non-Goals)
   - 満たすべき受け入れ基準(何が起きれば「完成」と言えるか)
   - 既知の制約(技術・期限・互換性など)
3. `.specs/<slug>/spec.md` を以下の構成で書く。

   ```markdown
   # Spec: <機能名>

   ## 背景・問題
   なぜこれが必要か。

   ## ゴール
   - ...

   ## Non-Goals(やらないこと)
   - ...

   ## ユーザーストーリー / ユースケース
   - As a ..., I want ..., so that ...

   ## 受け入れ基準
   - [ ] ...(検証可能な形で書く。曖昧な形容詞を避ける)

   ## 制約・前提
   - ...

   ## オープンな疑問(あれば)
   - ...
   ```

4. `.specs/<slug>/STATE.md` の `current_phase` を `spec` に、フェーズ進捗の `spec` にチェックを入れ、`updated_at` を更新する。
5. ユーザーに `spec.md` の内容を要約して提示し、確定してよいか確認する。確定したら次は `spec-design` に進むことを案内する。
