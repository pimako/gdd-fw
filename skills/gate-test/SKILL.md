# gate-test — 統合/システム/受け入れテスト

`gate-build` が単体テストまでを担当するのに対し、このスキルは**単体テストの範囲を超える検証**(ISTQBでいう統合テスト・システムテスト・受け入れテスト)を担当する。ここでの合否は機械的・客観的なテスト結果のみに基づき、ペルソナによる価値判断は行わない(それは次の`gate-check`の役割)。

## 前提チェック

`.specs/stories/<slug>/TASKS.md` の実装が実質的に未着手の場合は、先に `gate-build` を進めるようユーザーに促す。

## 手順

1. `STORY.md`(Gherkin Scenario)と実装差分を集める。
2. **gate-tester** サブエージェント(Agent tool)に渡し、以下を依頼する:
   - **統合テスト**: 変更したコンポーネントが既存の他コンポーネント・外部サービスと正しく連携するか
   - **システムテスト**: 統合されたシステム全体として期待される機能(該当すれば非機能要件)を満たすか
   - **受け入れテスト**: STORY.mdの各Scenarioを実際のテストとして実行する
3. `.specs/stories/<slug>/TEST.md` にScenario単位・テストレベル単位で結果を記録する。
4. テストが失敗する場合は `gate-build` に差し戻す(実装の問題として機械的に往復してよい。ここでは都度人間の判断を挟まなくてよい)。
5. 全て合格したら、ステータスを更新し次は `gate-check` に進むことを案内する。

## TEST.md フォーマット

```markdown
# Test: <ストーリータイトル>

## 統合テスト
- ...(結果)

## システムテスト
- ...(結果、該当する非機能要件があれば)

## 受け入れテスト(Scenarioごと)
- [x] <Scenario名>: PASS
- [ ] <Scenario名>: FAIL(理由: ...)

## 未カバーの項目・既知の制約
- ...
```
